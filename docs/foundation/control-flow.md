# 第 012 讲 · 分支：if / elif / else 与 match-case

> match-case 不是 switch：它做的是结构模式匹配，能解包序列、匹配映射、绑定子结构，能力远超值相等判断。本讲的目标是「写出层次清晰、可维护的条件逻辑」。先建立直觉，再用可运行代码把规则固定下来，最后放进工程场景里看边界与代价；全程建议边读边改参数、边猜输出。

## 1. 先建立直觉

**条件表达式与嵌套**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。

**match-case 结构模式**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

**守卫与捕获**。建议把它和相邻知识点连成一条线：输入是什么、状态存在哪里、失败时谁负责收尾。这三问能覆盖绝大多数线上问题，也是后续阶段反复使用的分析框架；能回答这三问，才算真正掌握而不是记住了 API 名字。

## 2. 语法与规则：把行为跑出来

### 2.1 主示例

**条件表达式与嵌套**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

```python
def grade(score):
    match score:
        case 90..100: return "A"
        case 80..89:  return "B"
        case _:        return "C"

print([grade(x) for x in [95, 83, 60]])
```
