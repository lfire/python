# 阶段导览 · 分布式云原生

单机服务总有一天会碰到边界：一台机器扛不住、一次调用跨了多个服务、或者某个依赖突然不可用。这个阶段处理的就是「当网络不再可靠」之后的设计问题。

从 CAP 与一致性模型开始，经过幂等与限流、分布式事务、ID 与分片、Raft 共识，再到容器化与 Kubernetes、GitOps 与灰度、任务调度与 SRE，最后落到安全工程。递进顺序是「先承认失败必然发生 → 再设计收敛与补偿 → 最后谈怎么稳定地交付和回滚」。第一百零七讲的事务方案与第一〇九讲的 Raft 偏理论，允许分两次读；第一一〇讲之后则更偏落地，建议对着一份真实部署清单看。

这一阶段和前面最大的不同是：很多问题没有唯一正确答案，只有带代价的取舍。我们要求每个方案都写清失效信号与回退路径，而不只是给出架构图。需要你已具备服务端、并发与工程化的基本经验。

## 这个阶段解决什么问题

一致性、幂等、分布式事务、分片、容器与 K8s、调度、SRE、安全。阶段划分不是按知识点罗列，而是按「学完能交付什么」倒推：前一阶段的输出正好是这一阶段的前置，跳过某一段往往会在后面某讲突然卡住，届时再回来补齐比按顺序学更费时。
