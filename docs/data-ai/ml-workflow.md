# 第 097 讲 · 机器学习流程：特征、划分与评价

> 评估的可信度取决于划分：先在全量数据上做特征选择或标准化再划分，就是典型的数据泄漏，分数虚高。本讲的目标是「建立不会自欺的建模与评估流程」。先建立直觉，再用可运行代码把规则固定下来，最后放进工程场景里看边界与代价；全程建议边读边改参数、边猜输出。

## 1. 先建立直觉

**训练集 / 验证集 / 测试集**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。

**数据泄漏**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

**特征工程与缩放**。建议把它和相邻知识点连成一条线：输入是什么、状态存在哪里、失败时谁负责收尾。这三问能覆盖绝大多数线上问题，也是后续阶段反复使用的分析框架；能回答这三问，才算真正掌握而不是记住了 API 名字。

## 2. 语法与规则：把行为跑出来

### 2.1 主示例

**训练集 / 验证集 / 测试集**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

```python
# 决策边界直觉：最近邻分类
from collections import Counter
train = [(1, "A"), (2, "A"), (8, "B")]
def knn(x, k=2):
    near = sorted(train, key=lambda t: abs(t[0]-x))[:k]
    return Counter(label for _, label in near).most_common(1)[0][0]
print(knn(3), knn(7))
```

### 2.2 对照写法

```python
def train_val_split(xs, ratio=0.8):

    return xs[:n], xs[n:]

```
