## 2. 语法与规则：把行为跑出来

### 2.1 主示例

**张量与设备**。建议把它和相邻知识点连成一条线：输入是什么、状态存在哪里、失败时谁负责收尾。这三问能覆盖绝大多数线上问题，也是后续阶段反复使用的分析框架；能回答这三问，才算真正掌握而不是记住了 API 名字。

```python
# LLM 应用：成本与上下文预算
def budget(tokens, price_per_1k=0.002):
    return round(tokens / 1000 * price_per_1k, 4)
print(budget(3500))
```

### 2.2 对照写法

```python
def chunk(text, size=4):
    return [text[i:i+size] for i in range(0, len(text), size)]
print(chunk("abcdefg"))
```

## 3. 深入一步：规则与边界

**Dataset / DataLoader**。这里的关键词是「什么时候」和「代价是什么」。Python 的机制大多不是非黑即白的开关，而是在可读性、性能与灵活性之间做的取舍。把取舍写清楚，遇到新版本或新框架时才能自己推导，而不是重新背一遍结论。

**损失与优化器**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。
