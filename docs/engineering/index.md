# 阶段导览 · 工程化

代码在自己机器上跑对，和能被同事接手、能在 CI 里稳定复现，是两件不同的事。这个阶段处理的就是中间这段距离：把脚本变成工程。

我们从项目结构与 src 布局出发，依次讲依赖与锁文件、代码规范、静态检查、pytest、Mock 与测试替身、属性测试与基准测试、日志、配置管理、打包发布，最后用「把脚本重构成可发布包」收束。递进是「能跑 → 能测 → 能发布 → 能回归」。其中第七十二讲的锁文件和第七十五讲的 fixture 最值得动手做一遍，因为它们决定了半年后别人还能不能把你的环境复原出来。

建议边学边拿自己之前写的小工具开刀：每读一讲就改一处，跑一次测试，比另起一个练习项目更容易坚持。有经验的人可以跳过规范那一讲，但不建议跳过打包发布——本地能导入、发布后却 `ModuleNotFoundError` 是极常见的事故，而 src 布局正是为了提前暴露它。

## 这个阶段解决什么问题

项目结构、依赖与锁、规范与类型、测试与 Mock、日志配置、打包与 CI/CD。阶段划分不是按知识点罗列，而是按「学完能交付什么」倒推：前一阶段的输出正好是这一阶段的前置，跳过某一段往往会在后面某讲突然卡住，届时再回来补齐比按顺序学更费时。
