# 第 071 讲 · 项目结构与 src 布局

## 1. 先建立直觉

**src 与扁平布局对比**。这里的关键词是「什么时候」和「代价是什么」。Python 的机制大多不是非黑即白的开关，而是在可读性、性能与灵活性之间做的取舍。把取舍写清楚，遇到新版本或新框架时才能自己推导，而不是重新背一遍结论。

**包与模块命名**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。

**内部模块分层**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

### 2.1 主示例

**src 与扁平布局对比**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。

```python
import subprocess, sys
checks = [
    [sys.executable, "-m", "compileall", "-q", "src"],
    [sys.executable, "-c", "print('lint ok')"],
]
for cmd in checks:
    r = subprocess.run(cmd, capture_output=True, text=True)
    print(r.returncode, r.stdout.strip() or "ok")
```
