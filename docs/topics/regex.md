# 正则表达式 re：从字符类到回溯

前面 132 讲里，爬虫解析、日志清洗、表单校验都零散用过 `import re`，但每次只取一个够用的片段，没交代这门小语言怎么读、何时会反过来拖垮程序。真正卡人的不是写不出匹配，而是字段边界一变就多抓漏抓、一条恶意输入把 CPU 打满、事后看不懂那串转义。这一篇按阅读顺序铺开：先规定单个字符的取值（字符类），再规定重复几次（量词与贪婪），接着把命中片段结构化取出（分组、命名捕获与 `re` 各 API），然后处理只判位置、不消费字符的断言，之后算清回溯代价、划清与字符串方法的边界，最后落到日志、表单、清洗的常用模式与可维护写法。动一条正则前，先清楚它匹配什么、最坏跑多久。

## 字符类与预定义类：先把「一个字符」的取值范围写死

正则的最小单位是某个位置上的一个字符，字符类就是给这个位置列出允许的取值。方括号 `[abc]` 表示这一个字符可以是 `a`、`b`、`c` 中的任意一个；`[0-9]`、`[a-z]`、`[A-Za-z_]` 用连字符给出连续区间；开头加 `^` 表示取反，`[^0-9]` 是除数字外的任意一个字符，注意它仍然要消费一个字符，不是「跳过」。多数元字符进了方括号就失去特殊含义，但 `]`、反斜杠、以及位于首位的 `^` 仍需谨慎，稳妥做法是转义或调整顺序。想匹配字面量的 `-`，把它放在首尾最省事。

预定义类是常用字符类的缩写，写起来短，但读的时候要清楚它到底覆盖哪些码位。默认 Unicode 模式下 `\w` 会匹配汉字、`\d` 会匹配全角数字，这既是便利也是事故源，解析纯 ASCII 协议时要显式加 `re.ASCII` 或干脆写显式区间。

| 写法 | 覆盖范围（Unicode 模式） | 含义 | 容易踩的边界 |
| --- | --- | --- | --- |
| `\d` | 比 `[0-9]` 更宽 | 任意 Unicode 十进制数字 | 全角「３」也算命中，表单校验需收紧 |
| `\w` | 字母、数字、下划线、汉字等 | 单词字符 | 中文算 `\w`，`\b` 的边界因此和英文语感不同 |
| `\s` | 空格、制表、换行等 | 空白字符 | 含换行符，`.` 默认不含 |
| `\D` `\W` `\S` | 对应大写类的补集 | 取反 | 仍各消费一个字符 |
| `\b` | 零宽 | 单词与非单词的交界 | 不消费字符，只断言位置 |
| `.` | 除换行外任意字符 | 通配 | 只有 `re.DOTALL` 下才包含换行 |

```python
import re

line = "订单 A-1392 金额 88.50 元，编号 b_007 作废"

print(re.findall(r"[A-Z]-\d+", line))        # ['A-1392']
print(re.findall(r"\d+\.\d+", line))         # ['88.50']
print(re.findall(r"\b[a-z]_\d+\b", line))    # ['b_007']
print(re.findall(r"[^0-9.\s]+", "88.50 元"))  # ['元']
```

第三个模式里的 `\b` 就是零宽断言：它要求 `b` 左边是空格、`7` 右边是空格，自己不占结果。第四个模式把数字、点和空白全部排除，只剩汉字，演示了取反类同样会吃掉字符。

## 量词与贪婪：重复几次，以及「尽量多」这条默认规则

量词跟在一个原子后面，规定它出现几次。`*` 是零次或多次，`+` 是一次或多次，`?` 是零或一次，`{m}` 恰好 m 次，`{m,}` 至少 m 次，`{m,n}` 介于 m 到 n 次。最容易翻车的是默认贪婪：量词会先尽可能多地吃字符，只有整体匹配不下去时才逐个回吐。想取最短的一段，在量词后加 `?` 变为懒惰量词，例如 `.*?`、`+?`、`{2,4}?`。

| 量词 | 含义 | 懒惰写法 | 典型用途 |
| --- | --- | --- | --- |
| `*` | 0 次或多次 | `*?` | 可选且可重复的空白 |
| `+` | 1 次或多次 | `+?` | 至少一位的数字、非空字段 |
| `?` | 0 或 1 次 | `??` | 可选前缀、可选符号 |
| `{m}` | 恰好 m 次 | 无 | 定长编码、年份四位 |
| `{m,n}` | m 到 n 次 | `{m,n}?` | 长度受限的密码、编号 |

```python
import re

s = 'name="alice" age="30" city="x"'

print(re.findall(r'"(.*)"', s))     # ['alice" age="30" city="x']
print(re.findall(r'"(.*?)"', s))    # ['alice', '30', 'x']
print(re.findall(r'"([^"]*)"', s))  # ['alice', '30', 'x']
```

同一份输入，贪婪版一路吃到最后一个引号，把三组值并成了一组；懒惰版在每遇到一个右引号时就收手。第三种写法用取反字符类 `[^"]*` 表达「引号内的任意非引号字符」，语义更直接，也不依赖引擎反复回吐，遇到值里含转义引号时比懒惰量词更可控。

### 懒惰量词不等于「更正确」

懒惰只改变引擎回退的方向，不改变「会不会回溯」。`(.*?)</div>` 面对一段没有闭合标签的长文本，仍会从左到右把每个位置都试一遍。真正消除不确定性靠的是把 `.` 换成取反类、把量词写成定长，或者在可维护性和确定之间选一个明确边界，而不是无脑给每个量词补 `?`。

## 分组、命名捕获与反向引用：把命中结果变成字典

圆括号 `()` 同时做两件事：把多个原子绑成一个整体供量词作用，并把括号内命中的内容存为捕获组。`(?:...)` 只分组、不捕获，既能让 `findall` 不返回多余的元组元素，也省下一个编号。编号组用 `\1`、`\2` 在模式内部反向引用，在 `sub` 的替换串里写 `\1` 或 `\g<1>`；但只要在前面插入一对新括号，所有编号就集体错位，工程里更该用命名捕获 `(?P<name>...)`，模式内用 `(?P=name)` 回引，替换串里用 `\g<name>`，代码里用 `m.group('name')` 或 `m.groupdict()` 取值。

```python
import re

# (?P=quote) 要求收尾引号与起始引号一致，避免跨字段误配
pat = re.compile(r'(?P<key>\w+)=(?P<quote>["\'])(?P<value>.*?)(?P=quote)')
text = 'user="alice" role="admin" level="3"'

for m in pat.finditer(text):
    print(m.groupdict(), m.span())
# {'key': 'user', 'quote': '"', 'value': 'alice'} (0, 12)
# {'key': 'role', 'quote': '"', 'value': 'admin'} (13, 25)
# {'key': 'level', 'quote': '"', 'value': '3'} (26, 35)
```

`groupdict()` 直接给出「键到值」的字典，字段含义写在模式里而不是靠 `m.group(2)` 这种位置记忆；三个月后回头改需求，新增一个捕获组也不会让已有代码悄悄取错列。注意 `(?P<name>...)`、`(?P=name)`、`\g<name>` 这类写法里的尖括号是语法的一部分，落到正文或表格里也要整体包进反引号，别让渲染器把它们当成标签。

## 零宽断言与锚点：只判定位置，不把字符吃进来

锚点 `^`、`$`、`\A`、`\Z` 与 `\b`、`\B` 都是零宽的：断言当前位置满足某条件，不匹配任何字符，因此不会出现在结果里。`^` 和 `$` 受 `re.MULTILINE` 影响，含义变成每行首尾；`\A` 和 `\Z` 永远指整串首尾，做整串格式校验时用后者更严。前瞻 `(?=...)`、`(?!...)` 向右看，后顾 `(?<=...)`、`(?<!...)` 向左看；标准库要求后顾定长，写 `(?<=\d+)` 会报错，需要变长后顾得换第三方 `regex` 库。

```python
import re

# 1) 密码复杂度：多个前瞻从同一位置分别检查，互不消费字符
pwd = re.compile(r'(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[\w!@#]{8,}\Z')
print([bool(pwd.match(s)) for s in ("abc12345", "Abc12345", "Abc1!xyz")])
# [False, True, True]

# 2) 千分位：只在左边是数字、右边剩 3 的倍数个数字的间隙插入逗号
print(re.sub(r'(?<=\d)(?=(\d{3})+\b)', ',', '1234567890'))
# 1,234,567,890

# 3) 前瞻取价格，但不把单位带进结果
print(re.findall(r'\d+\.\d{2}(?= 元)', '小计 88.50 元，共 128.00 元'))
# ['88.50', '128.00']
```

三个例子分别对应「叠加约束」「在间隙插入」「带条件的提取」。第 2 个模式里 `(?<=...)` 与 `(?=...)` 都不消费字符，所以 `sub` 只插入逗号、不动数字；第 3 个模式用前瞻核对紧随其后的单位，结果里却不含这两个汉字。

## re 模块六个 API 的分工：从「找不找得到」到「逐个处理」

`re.match` 只从字符串开头试一次，`re.search` 扫到第一个命中就停，`re.fullmatch` 要求整串贴合、是做格式校验的首选。`re.findall` 一次收齐所有命中：无捕获组时返回字符串列表，有组时返回元组列表，且丢掉位置信息。`re.finditer` 返回 `Match` 迭代器，能拿 `span()`、`group()`、`groupdict()`，处理大文件时不必把结果一次装进内存。`re.sub` 做替换，替换串支持 `\g<name>` 引用命名组，也能传一个函数按命中内容动态生成新值。`re.compile` 把模式预编译成 `Pattern` 对象，复用时省去重复解析，并统一挂上标志位。模块级函数 `re.search(pattern, s)` 内部也走缓存，只有同一模式被高频调用时才明显值得显式 `compile`。

| 函数 | 匹配起点 | 命中数量 | 返回值 | 是否带位置 | 分组处理方式 |
| --- | --- | --- | --- | --- | --- |
| `re.match` | 仅开头 | 首个或失败 | `Match` 或 `None` | 是 | `m.group(n)` |
| `re.search` | 任意位置 | 首个或失败 | `Match` 或 `None` | 是 | `m.group(n)` |
| `re.fullmatch` | 整串 | 全串贴合 | `Match` 或 `None` | 是 | `m.groupdict()` |
| `re.findall` | 全局 | 全部 | 字符串或元组列表 | 否 | 有组时自动只返回组 |
| `re.finditer` | 全局 | 全部 | `Match` 迭代器 | 是 | `m.span()` 与 `m.groupdict()` |
| `re.sub` | 全局 | 全部 | 新字符串 | 否 | 替换串用 `\g<name>` |

```python
import re

log = "WARN 2026-11-13 disk=91% host=db-2"

print(re.match(r'WARN', log) is not None)        # True
print(re.match(r'disk', log) is not None)        # False
print(re.search(r'disk=(\d+)%', log).group(1))   # 91
print(re.findall(r'(\w+)=(\S+)', log))           # [('disk', '91%'), ('host', 'db-2')]
print([(m.group(), m.span()) for m in re.finditer(r'\d+%', log)])
# [('91%', (21, 24))]
print(re.sub(r'(?P<k>\w+)=(?P<v>\S+)', r'\g<k>:\g<v>', log))
# WARN 2026-11-13 disk:91% host:db-2

pat = re.compile(r'\b[A-Z]{3,}\b')
print(pat.findall(log))                          # ['WARN']
```

第二行的 `False` 是新手最常撞的墙：`match` 不扫描字符串中间，要找中间内容得用 `search`。`findall` 因为模式里带了两个捕获组，返回的是元组列表而不是整段命中，这一点在处理日志时尤其容易忽略。

## 标志位：改的是元字符的含义，不是匹配结果

标志位不改变「匹配什么文本」的业务目标，改变的是几个元字符的解释方式。多个标志用按位或组合，例如 `re.compile(pat, re.I | re.M | re.X)`。

| 标志 | 缩写 | 影响的元字符 | 典型场景 |
| --- | --- | --- | --- |
| `re.IGNORECASE` | `re.I` | 大小写匹配 | 日志级别、用户输入的命令 |
| `re.MULTILINE` | `re.M` | `^` 与 `$` 改为每行首尾 | 逐行处理多段文本 |
| `re.DOTALL` | `re.S` | `.` 包含换行 | 跨行提取 HTML 片段 |
| `re.VERBOSE` | `re.X` | 忽略空白、允许 `#` 注释 | 长模式分行书写 |
| `re.ASCII` | `re.A` | `\w` `\d` `\s` `\b` 退回 ASCII | 协议字段、纯英文标识符 |

`re.VERBOSE` 值得单独留意：开启后模式里的字面空格必须用 `\ ` 或 `[ ]` 表示，`#` 之后到行尾全被当作注释。它把正则从一行密文变成可加注释的小段代码，是长模式最有效的可读性手段。

## 回溯与灾难性匹配：算清最坏情况要跑多久

引擎遇到量词会先贪婪吃满，失败时回退一个字符再试，这个「试错—回退」就是回溯。嵌套量词 `(a+)+` 面对「整体看似匹配、末尾却差一个字符」的输入时，会把同一串字符的所有划分方式指数级枚举一遍：CPU 被钉死，内存几乎不动，这就是灾难性回溯，也常被称为 ReDoS。把用户可控输入直接喂给含嵌套量词或多分支的正则（邮箱、URL、标签校验最典型），等于给接口留了一个只要发一条长字符串就能打满 CPU 的入口。

```python
import re
import time

bad = re.compile(r'(a+)+$')
for n in (10, 14, 18, 22):
    s = 'a' * n + 'b'          # 末尾的 b 让整体必然失败，逼出全部回溯
    t = time.perf_counter()
    bad.search(s)
    print(n, round(time.perf_counter() - t, 4))
# 10 0.0001
# 14 0.002
# 18 0.028
# 22 0.28   ← 长度每 +4，耗时约翻十几倍（示意，数值随机器变化）
```

### 用占有量词与原子组锁死回退

Python 3.11 起支持占有量词 `*+`、`++` 与原子组 `(?>...)`：它们一旦吃掉字符就不再回吐，从根上掐掉指数级枚举。改写后的模式面对同样输入是线性时间。

```python
import re
import time

evil = 'a' * 20 + 'b'
for label, pat in (("嵌套量词", r'(a+)+$'), ("原子组", r'(?>a+)+$'), ("占有量词", r'a++$')):
    t = time.perf_counter()
    re.search(pat, evil)
    print(label, round(time.perf_counter() - t, 4))
# 嵌套量词 0.06xx   ← 示意：呈指数增长，长度再往上会迅速失控
# 原子组 0.0
# 占有量词 0.0
```

把输入长度控制在 20 左右就能在毫秒级看到三者的差距，再往上第一个模式会迅速失控，所以别拿生产流量去试。修复顺序一般是：先用取反字符类替换 `.*`，把嵌套量词改写成等价的单层形式，再考虑原子组或占有量词，最后对不可信输入补一层超时兜底。

## 正则与字符串方法：先问「这活儿需不需要模式」

判断前缀、后缀、包含，用 `str.startswith`、`str.endswith`、`in`；按固定分隔符拆，用 `str.split` 或 `partition`；去首尾空白用 `strip`；大小写归一用 `casefold`。这些写法可读、没有回溯风险，通常也更快。只有规则涉及「分隔符不固定」「按结构取字段」「校验格式」「按内容动态替换」时才值得上正则。一个实用的判据是：能用一个 `if` 或一次 `split` 说清的，别写正则；写起来要三层 `if` 嵌套处理边界的，正则往往更短更准。

| 需求 | 字符串方法 | 什么时候必须换成正则 |
| --- | --- | --- |
| 判断包含、前缀、后缀 | `in`、`startswith`、`endswith` | 需要忽略大小写且要求单词边界 |
| 按固定串拆分 | `split(',')` | 分隔符是可变空白或多种符号 |
| 去首尾空白 | `strip()` | 要把串内任意空白折叠成一个 |
| 简单替换 | `replace(old, new)` | 按分组结构动态生成替换值 |
| 格式校验 | 手写条件组合 | 长度、字符类、位置约束叠加 |

```python
import re

row = "  alice , 30 ,  admin  "
print([c.strip() for c in row.split(',')])       # ['alice', '30', 'admin']
print(re.split(r'\s*,\s*', row.strip()))         # ['alice', '30', 'admin']
print(re.findall(r'\S+', "a   b\tc\nd"))         # ['a', 'b', 'c', 'd']
```

前两行结果相同：固定逗号拆分用 `split` 更直白，只有当逗号两侧空白数量不确定时，`re.split` 的模式才体现出价值。第三行展示「按任意空白切分」这一字符串方法不擅长的场景。

## 日志、表单与数据清洗的常用模式

把常见形状收成一个可改的模式库，比每次从零拼字符串更可靠。要点是「按业务收紧」：别拿一条号称万能的正则去校验邮箱或 URL，能枚举的取值就写成枚举，能定长就写定长，能加锚点就加锚点。

| 场景 | 模式骨架 | 收紧手段 |
| --- | --- | --- |
| 时间戳 | `(?P<ts>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})` | 定长 `{2}` `{4}`，命名组 |
| 日志级别 | `(?P<level>DEBUG\|INFO\|WARN\|ERROR)` | 用枚举代替 `\w+` |
| 键值字段 | `(?P<k>\w+)=(?P<v>\S+)` | 值不允许空白，配合 `finditer` |
| 中国大陆手机号 | `1[3-9]\d{9}` | 加 `\A` `\Z` 或 `fullmatch` |
| IPv4 段 | `(?:25[0-5]\|2[0-4]\d\|1?\d?\d)` | 分段限制 0 到 255，别只写 `\d{1,3}` |
| 形状校验日期 | `\d{4}-\d{2}-\d{2}` | 只校形状，合法性交给 `datetime` |
| 中间四位脱敏 | `(?<=\d{3})\d{4}(?=\d{4})` | 定长后顾与前瞻锁死位置 |

```python
import re

# 应用日志：时间、级别、消息、耗时，长模式按字段分段拼接更可读
LINE = (r'(?P<ts>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
        r'\[(?P<level>\w+)\] (?P<msg>.*?) '
        r'cost=(?P<cost>\d+)ms')
pat = re.compile(LINE)
rows = [
    "2026-11-13 09:12:03 [INFO] GET /api/user cost=18ms",
    "2026-11-13 09:12:05 [WARN] GET /api/order cost=240ms",
]
for line in rows:
    m = pat.match(line)
    print(m.group('level'), m.group('msg'), m.groupdict()['cost'])
# INFO GET /api/user 18
# WARN GET /api/order 240

# 手机号中间四位脱敏，保留前 3 后 4
print(re.sub(r'(?<=\d{3})\d{4}(?=\d{4})', '****', '联系 13812345678'))
# 联系 138****5678

# 折叠任意空白，清洗表单输入
print(re.sub(r'\s+', ' ', '  张\t三 \n 备注  ').strip())
# 张 三 备注
```

注意日期那类模式只保证形状，`2026-13-40` 也会通过，真正判断是否为合法日期应把字符串交给 `datetime.strptime` 再捕获 `ValueError`，别把日历规则硬塞进正则。

## 可维护性：命名组、re.VERBOSE 与超时

命名组让 `groupdict()` 自带字段名，重构时插入新括号不破坏编号；`re.VERBOSE` 允许多行、缩进和 `#` 注释，把长模式当小段代码写；关键模式配一组正反例单元测试，改动后能立刻知道匹配行为有没有漂移。另外，`re` 缓存最近约 512 个模式，循环里别反复 `re.compile` 同一串，也别把用户原样文本拼进模式。标准库 `re` 没有超时参数，处理不可信输入要么先截断长度、要么换支持 `timeout` 的第三方库。

```python
import re

PHONE = re.compile(r'''
    \A                 # 从整串开头
    1[3-9]             # 号段：1 开头，第二位 3 到 9
    \d{9}              # 后 9 位
    \Z                 # 到整串结尾
''', re.VERBOSE | re.ASCII)

for s in ("13812345678", "12812345678", "1381234567", "138123456789"):
    print(s, bool(PHONE.fullmatch(s)))
# 13812345678 True
# 12812345678 False
# 1381234567 False
# 138123456789 False
```

需要给匹配加超时保护时，安装第三方 `regex` 库（安装命令见下方），它的 `timeout` 参数以秒计，超时抛 `TimeoutError`。它对部分嵌套量词已做优化，但交替分支叠加量词仍会指数回溯，所以超时是最后一道保险，不能替代改写模式。

```python
import regex

# 交替分支 + 嵌套量词会枚举指数种划分，用 timeout（秒）兜底
try:
    regex.search(r'(a|aa)+$', 'a' * 30 + 'b', timeout=0.2)
    print('匹配结束')
except TimeoutError:
    print('超时，已放弃该输入')
# 超时，已放弃该输入
```

## 常见坑 / 边界与合规

1. **把用户输入直接拼进模式**：`re.search(user_input, text)` 既让元字符被当成语法，又给 ReDoS 开了门。修复：字面量一律用 `re.escape` 转义，对不可信输入先限制长度，再配合超时或改写后的线性模式。
2. **用 `^` 与 `$` 做整串校验**：`$` 允许匹配末尾换行之前的位置，`re.match(r'^\d+$', '123\n')` 会返回成功。修复：校验改用 `fullmatch`，或把锚点换成 `\A` 与 `\Z`。
3. **忽略 Unicode 语义**：`\w` 会放过一个汉字用户名，`\d` 会放过全角数字，协议字段因此被绕过。修复：加 `re.ASCII`，或写显式 `[0-9A-Za-z_]`，并给「应拒绝」的输入补反例测试。
4. **误用 `findall` 的返回结构**：模式里多了捕获组，结果就从字符串列表变成元组列表，且拿不到位置。修复：要位置就用 `finditer` 取 `span()` 与 `groupdict()`，非捕获的场景把分组改成 `(?:...)`。
5. **把脱敏当成合规的终点**：`sub` 只处理了匹配到的形状，日志里仍可能留有完整卡号、身份证或密钥原文。修复：在写入日志之前统一做字段级脱敏，配反向用例验证没有漏网格式，密钥类信息一律不进日志。

::: details 练习 1 · 用命名组解析 combined 日志
给定一行 nginx combined 日志，用命名捕获取出 `ip`、时间、请求方法、路径、状态码、字节数，打印 `groupdict()`。要求状态码必须是三位数字、字节数为纯数字或 `-`。

```python
# 参考解
import re

LINE = (r'(?P<ip>\S+) \S+ \S+ \[(?P<time>[^\]]+)\] '
        r'"(?P<method>GET|POST|PUT|DELETE) (?P<path>\S+) [^"]+" '
        r'(?P<status>\d{3}) (?P<bytes>\d+|-)')

log = '10.0.0.7 - - [13/Nov/2026:09:12:03 +0800] "GET /api/user?id=7 HTTP/1.1" 200 1532'
m = re.match(LINE, log)
print(m.groupdict())
# {'ip': '10.0.0.7', 'time': '13/Nov/2026:09:12:03 +0800',
#  'method': 'GET', 'path': '/api/user?id=7', 'status': '200', 'bytes': '1532'}
print(m.group('status'), m.group('bytes'))  # 200 1532
```

::: details 练习 2 · 改写一条会指数回溯的模式
下面两个模式都用来判断「整串是否只由字母 a 组成」：`(a+)+` 含嵌套量词，面对末尾带一个非 a 字符的长输入会指数回溯；`a+` 是等价的线性写法。用一组正反例证明两者对正常输入判定一致，并说明为什么后者没有多种划分方式。

```python
# 参考解
import re

danger = re.compile(r'(a+)+')
safe = re.compile(r'a+')

cases = ["a", "aaaa", "aaaab", "", "baaa"]
print([bool(danger.fullmatch(s)) for s in cases])
# [True, True, False, False, False]
print([bool(safe.fullmatch(s)) for s in cases])
# [True, True, False, False, False]
print([bool(danger.fullmatch(s)) == bool(safe.fullmatch(s)) for s in cases])
# [True, True, True, True, True]
# danger 的外层 + 把同一串 a 切成若干段，段与段之间有多种划分，
# 失败输入要把这些划分全试一遍；safe 只有一次 a+，没有可回退的分段点。
```
:::
