# 第 017 讲 · 序列协议与通用操作

> Python 的容器不是各自为政：只要实现 __len__ 与 __getitem__，索引、切片、in、迭代就基本可用。本讲的目标是「理解所有序列共享的一套接口」。先建立直觉，再用可运行代码把规则固定下来，最后放进工程场景里看边界与代价；全程建议边读边改参数、边猜输出。

## 1. 先建立直觉

**序列与可迭代的区别**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。

**__len__ 与 __getitem__**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

**索引与切片协议**。建议把它和相邻知识点连成一条线：输入是什么、状态存在哪里、失败时谁负责收尾。这三问能覆盖绝大多数线上问题，也是后续阶段反复使用的分析框架；能回答这三问，才算真正掌握而不是记住了 API 名字。

## 2. 语法与规则：把行为跑出来

### 2.1 主示例

**序列与可迭代的区别**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

```python
rows = [[0] * 3] * 3
rows[0][0] = 9
print(rows)
fixed = [[0] * 3 for _ in range(3)]
fixed[0][0] = 9
print(fixed)
```
