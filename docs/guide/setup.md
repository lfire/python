# 第 002 讲 · 环境与工具链：解释器、虚拟环境与编辑器

> 环境问题的本质是三个变量没对齐：解释器版本、依赖集合、工作目录；把它们全部写进配置文件，换机器才能一行复原。本讲的目标是「搭好可复现、可隔离、可协作的开发环境」。先建立直觉，再用可运行代码把规则固定下来，最后放进工程场景里看边界与代价；全程建议边读边改参数、边猜输出。

## 1. 先建立直觉

**CPython 与 PyPy 等实现**。从实现角度看，这一层的行为最终会落到对象协议、字节码或运行时状态上。理解底层并不意味着每次都要写底层代码，而是当现象与直觉不符时，你知道该用 dis、inspect、tracemalloc 还是 cProfile 去验证，从而把猜测变成证据。

**pyenv / uv 的版本管理**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

## 2. 语法与规则：把行为跑出来

### 2.1 主示例

**CPython 与 PyPy 等实现**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。

import sys, platform
