## 2. 语法与规则：把行为跑出来

### 2.1 主示例

**栈式指令与 LOAD / STORE**。这里的关键词是「什么时候」和「代价是什么」。Python 的机制大多不是非黑即白的开关，而是在可读性、性能与灵活性之间做的取舍。把取舍写清楚，遇到新版本或新框架时才能自己推导，而不是重新背一遍结论。

```python
import ast, dis
src = "x = 1 + 2 * 3"
tree = ast.parse(src)
print(ast.dump(tree, include_attributes=False)[:70])
dis.dis(compile(src, "<s>", "exec"))
```

## 4. 工程实践

排查诡异行为时先 dis 一小段，再决定是语言规则、优化还是库的问题；性能热点也常在这里显形 **版本间指令变化**。建议把它和相邻知识点连成一条线：输入是什么、状态存在哪里、失败时谁负责收尾。这三问能覆盖绝大多数线上问题，也是后续阶段反复使用的分析框架；能回答这三问，才算真正掌握而不是记住了 API 名字。 落地时把这条结论写进检查表或自动化测试，避免只停留在口头约定。

本机不用起服务，一条命令就能把本讲的关键行为再验证一次：

```bash
python -c "import dis; dis.dis(lambda x: x+1)"
```
