# 第 049 讲 · CPython 编译流程：AST 到字节码

> 解释器执行的是编译后的字节码，源码只参与最前面一步；用 ast 改写代码结构比字符串替换可靠得多。本讲的目标是「能读懂并操作 Python 的编译中间产物」。先建立直觉，再用可运行代码把规则固定下来，最后放进工程场景里看边界与代价；全程建议边读边改参数、边猜输出。

### 2.1 主示例

**词法与语法分析**。先把这个概念放进可验证的场景：写一段最小代码，观察它的输出，再回头读规则。很多误解来自只记结论、没有亲手跑过边界情况；本讲要求把每一步的结论都用一段可运行代码固定下来，而不是停在「大概是这样」。

```python
import sys
def depth(n):
    print("frame", n, bool(sys._getframe().f_back))
    if n: depth(n-1)
depth(1)
```

import dis
def gen():

## 3. 深入一步：规则与边界

## 4. 工程实践

自定义 lint、代码生成、自动插桩都应基于 AST；产物要保留 lineno 与 col_offset **常量折叠**。工程里最容易出问题的不是不会用，而是用在错误的边界上：数据规模变大、并发进入、依赖升级、跨平台部署之后，原本成立的假设会逐个失效。因此本讲同时给出适用条件、失效信号和一条可回退的路径。 落地时把这条结论写进检查表或自动化测试，避免只停留在口头约定。

### 用命令行复现

本机不用起服务，一条命令就能把本讲的关键行为再验证一次：

```bash
python -c "import dis; dis.dis(lambda x: x+1)"
```

把命令里的输入换成你自己的数据，观察输出是否仍符合 **词法与语法分析** 的规则；若结果不一致，先核对 Python 版本与依赖版本，再回到主示例逐行定位差异。这条命令也可以直接加进 CI，作为本讲结论的回归检查。
